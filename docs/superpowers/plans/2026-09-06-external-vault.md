# External Vault Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let `SUPER_GOAL_ROOT` be an absolute or `~`-prefixed path so the goal vault lives outside the checkout as its own git repository, and give `superagent:init` a `--local-only` flag, so superagent can be run on a repository (this plugin's own checkout first) without committing any vault, config, or role-agent artifact into it.

**Architecture:** One resolver (`vault_root` / `vault_is_external` in `scripts/_common.sh`, mirrored by a canonical **Vault root** prose block in the skills) replaces every hand-joined `<repo-root>/<SUPER_GOAL_ROOT>`. superauthor A7 gains a target repo: in external mode it always uses its existing direct-commit variant against the vault repo. superloop L1 roots the loop-status file at the resolved vault; L5 adds a `sync_vault()` step and a two-kind be-sure rule. `launch.sh` accepts a plan under the external vault and stores its absolute path. init creates/initialises the vault repo, stops writing the loop-status pattern into the code repo in external mode, and routes ignore entries to `.git/info/exclude` under `--local-only`. Relative `SUPER_GOAL_ROOT` values keep today's behaviour byte for byte.

**Tech Stack:** bash 3.2-compatible shell (macOS `/bin/bash`), markdown skill files, the three harness build scripts (`scripts/build-{codex,cursor,pi}-skills.sh`), offline shell tests in the style of `scripts/prd-lint-test.sh` / `scripts/bridge-test.sh`.

**Spec:** `docs/superpowers/specs/2026-09-06-external-vault-design.md`

## Global Constraints

- Every shell change must run under bash 3.2 (`/bin/bash --version` on this Mac): no associative arrays, no `${var,,}`, no `mapfile`, no `declare -A`.
- Relative `SUPER_GOAL_ROOT` values (the shipped default `vault`) must behave exactly as before this plan: same paths, same PR flow, same `.gitignore` line. Every test that exists today must still pass.
- Skills never `git add -A`; explicit paths only. init never commits to the user's code repo (the one exception is the external vault repo's first commit, Task 4).
- No `Co-Authored-By` or Claude attribution trailers in commits (repo policy, superauthor A7).
- `SUPER_PROTECTED_MAIN` describes the **code** repo only; the external vault repo always takes direct commits.
- `master_plan:` in a loop file is repo-relative in internal mode (unchanged) and absolute in external mode.
- The canonical skills are `skills/*/SKILL.md`; `codex/`, `cursor/`, `pi/` are generated by the build scripts and must be regenerated (never hand-edited) in Task 7.
- Work on branch `feat/external-vault` (already exists, holds the spec commit). Version ships as `0.7.1`.
- Prose style in skills follows the neighbouring text: worked examples in parentheses, `<placeholders>` in angle brackets, bold for MUST/never.

```bash

# ---------------------------------------------------------------------------
# Goal-vault location. SUPER_GOAL_ROOT is repo-relative by default (`vault`) — the
# vault lives inside the checkout and its docs are committed there via PR. An
# ABSOLUTE or ~-prefixed value selects EXTERNAL mode: the vault is its own git
# repo outside the checkout, and vault docs are committed there instead, so the
# code repo's history never carries the plan tree (spec:
# docs/superpowers/specs/2026-09-06-external-vault-design.md).
# ---------------------------------------------------------------------------

# vault_is_external — rc 0 when SUPER_GOAL_ROOT is absolute or ~-prefixed.
vault_is_external() {
  case "${SUPER_GOAL_ROOT:-vault}" in /*|"~"|"~/"*) return 0 ;; *) return 1 ;; esac
}

# vault_root <primary-root> — absolute goal root in either mode, no trailing slash.
# Internal: <primary-root>/<SUPER_GOAL_ROOT>. External: the value itself (~ expanded).
vault_root() {
  local primary="${1:-}" v="${SUPER_GOAL_ROOT:-vault}"
  [[ -n "$primary" ]] || { echo "superagent: vault_root needs the primary checkout root" >&2; return 1; }
  v="${v%/}"
  case "$v" in
    "~")   printf '%s\n' "$HOME" ;;
    "~/"*) printf '%s/%s\n' "$HOME" "${v#"~/"}" ;;
    /*)    printf '%s\n' "$v" ;;
    *)     printf '%s/%s\n' "${primary%/}" "$v" ;;
  esac
}
```

# ---- 3. init ignore-entry routing rules (the shell the skill text prescribes) ------------------
# append_ignore <file> <line> — Step 5's rule: newline guard, then append unless an identical
# line is present. The skill text in skills/init/SKILL.md must match this function.
append_ignore() {
  local f="$1" line="$2"
  if [[ -s "$f" && "$(tail -c1 "$f" | od -An -c | tr -d ' ')" != '\n' ]]; then printf '\n' >>"$f"; fi
  grep -qxF -- "$line" "$f" 2>/dev/null || printf '%s\n' "$line" >>"$f"
}
mkdir -p "$T/ini"; ( cd "$T/ini" && git init -q )
printf 'node_modules' >"$T/ini/.gitignore"            # no trailing newline: the guard must fire
append_ignore "$T/ini/.gitignore" ".env"; append_ignore "$T/ini/.gitignore" ".env"; append_ignore "$T/ini/.gitignore" "vault/**/loop-status/"
check "init: newline guard + idempotent append into .gitignore" bash -c "[ \"\$(cat '$T/ini/.gitignore')\" = \"\$(printf 'node_modules\n.env\nvault/**/loop-status/')\" ]"
EXCL="$T/ini/.git/info/exclude"

append_ignore "$EXCL" ".superenv"
